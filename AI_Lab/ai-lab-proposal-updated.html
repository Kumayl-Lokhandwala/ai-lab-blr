Executive summary

One shared AI service, two ways to host it.

The AI Lab gives employees a secure AI assistant for coding, summarising documents, research and questions on internal material. It runs two leading open models, Qwen3.6-35B-A3B for deep reasoning and Gemma-4-26B-A4B for fast answers, and a router sends each request to the better fit automatically.

We evaluated two ways to host it: three Apple Mac Studio M5 Ultra machines, or one server with an NVIDIA A100 80GB GPU. Cost and return are nearly identical. We recommend the Mac Studio lab: it stays online if a machine fails, uses far less power and runs with standard IT skills.

Data Sovereignty & Privacy

Complete in-house privacy, two security models.

By hosting open-weight models on hardware owned by the bank, no prompt, code snippet, or corporate data ever leaves the SCB perimeter. We evaluated two deployment approaches for enforcing data governance.

Baseline Model · Air-Gapped Perimeter Default

  • Physical Isolation: 100% on-premise inference inside the SCB corporate network; no external API calls.
  • Network Access: Authenticated LAN and VPN/Citrix tunnel endpoints with zero cloud route.
  • Passive Retention: 7-day ephemeral PostgreSQL session database with automated daily purge.

Alternative Model · Tri-Layer Active Harness Deep Inspection

  • Pre-Inference Secrets Scan: GitLeaks blocks committed tokens and API keys before payload hits the model.
  • Inbound Heuristic Filtering: LLM Guard + Presidio scrubs PII (Aadhaar, PAN, CC) and halts jailbreak injection attempts.
  • Outbound Policy Guard: NeMo Guardrails enforces dialogue boundaries and stops hallucinated data leakage.

Alternative Pipeline: In-Flight Inspection Flow

In the alternative model, every request passes through a containerized security harness executed before and after token generation:

Layer 1: GitLeaks

Runs deterministic regex and entropy scanning on code blocks to detect over 200 secret signatures (API tokens, private keys, database credentials) prior to model exposure.

Layer 2: LLM Guard + Presidio

Analyzes natural language prompts for indirect injection and jailbreak syntax while Microsoft Presidio redacts Indian financial identifiers (PAN, Aadhaar, account numbers).

Layer 3: NeMo Guardrails

Uses programmable Colang dialogue rules to verify model outputs against financial policy boundaries, check against source documents, and suppress hallucinated statements.

Recommendation: The Baseline Model satisfies initial pilot compliance. The Alternative Model is recommended if developers use the cluster directly for automated CI/CD code audits or threat intelligence processing.

AI Lab architecture

How the AI Lab works.

An employee signs in to the portal and books a session. Each request then passes through the gateway, which checks access and runs the safety checks; the router chooses the model, and the load balancer sends it to a free Mac Studio. Fair-use limits on each request keep the lab fast for everyone. Almost every component is proven, ready-made open-source software.

Where data is stored

All data stays on the lab's own hardware in the server rack. Nothing is saved on employees' computers.

Data Where How long
Chat history Mac mini, visible only to the user Deleted after 7 days of inactivity
Usage and violation logs Mac mini, backed up to lab storage As per bank policy
Settings and bookings Mac mini, backed up to lab storage Always the latest
AI models Each Mac Studio, master copy on lab storage Until updated
Passwords Not stored. Checked by Active Directory at login —

What happens if something fails

If this fails What happens
One Mac Studio Its work moves to the other two automatically. The lab keeps running.
Busy periods Requests queue briefly. Session bookings keep demand balanced.
A safety check (PII / harmful content) Requests pause until it is back, so nothing goes through unchecked.
Mac mini gateway Lab pauses briefly and is restored from the backup on lab storage.
Power cut UPS protects the hardware. Everything restarts automatically when power returns.
