01
The problem

No single model is fast and deep at once.

Deep-reasoning models are too slow for quick autocomplete. Fast models are too shallow for debugging across a whole codebase. Sending every request to the biggest model wastes GPU time — and the GPU's memory limit decides how many users the lab can serve at once.

Classify request→ Route to best model→ Serve from shared GPU
02
How Nexus works

Two models, one router, no wasted GPU cycles.

Every request moves through the same four-step loop.

01
Classify
The router looks at each request to see how hard it is and how fast it needs to be answered, before sending it anywhere.
02
Route
Simple, quick work — autocomplete, boilerplate, short answers — goes to Gemma-4-26B-A4B.
03
Reason
Harder work — debugging, refactoring, whole-codebase analysis — goes to Qwen3.6-35B-A3B for deeper thinking.
04
Serve
Both models stay loaded on the same A100 at all times, so switching between them takes no extra time.

Concurrency & load balancing

One GPU, seven lanes — nobody waits behind someone else's job.

MIG (Multi-Instance GPU) splits the A100 into up to seven separate lanes. A load balancer sits behind the router and sends each request to a free lane already running the right model — so a quick question never gets stuck waiting behind someone else's long, complex one, and the other way around.

Hybrid CPU + GPU Routing · Alternative Approach — SCB GBS Bangalore
Evaluated as a lower-CapEx alternative to Nexus

One workstation. Three model tiers. No cluster.

This approach splits each model's weights between GPU and CPU memory — instead of one GPU running two models, one workstation runs models up to 70B parameters by keeping only the frequently-used ("hot") weights on the GPU and offloading the rest ("cold") to CPU RAM. It trades some raw speed at the largest model size for a meaningfully smaller hardware bill.

03
The architecture

Exploiting neural sparsity — the PowerInfer approach.

Language models follow a power-law activation pattern: on any given query, roughly 20% of the neural weights do about 80% of the mathematical work. Rather than fitting an entire model in GPU VRAM, this approach separates the workload by how often each part is actually used.

01
Adaptive predictor
The system analyzes each incoming prompt and predicts exactly which neurons will be needed before heavy computation begins.
02
Intelligent routing
The ~80% of neurons that activate constantly ("hot") go to the GPU. The much larger, rarely-used knowledge base ("cold") is assigned to CPU RAM.
03
Synchronized assembly
CPU and GPU compute in parallel; the CPU's fragments cross the PCIe bus to the GPU, which stitches the final output together.
